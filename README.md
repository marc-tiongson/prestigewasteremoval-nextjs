# Prestige Waste Removal - Next.js

Independent repository: https://github.com/marc-tiongson/prestigewasteremoval-nextjs

Next.js 16 / React 19 migration of https://github.com/marc-tiongson/prestigewasteremoval. All 20 original URLs are statically generated by the Next.js Pages Router.

## Run

Use Node.js 20.9 or newer.

```sh
npm ci
npm run dev
```

Open http://localhost:3000.

```sh
npm run build
npm start
```

For Vercel, select **Next.js**, use the project root, build with `npm run build`, and keep the default Next.js output setting. The old static site's vercel.json inside the source archive does not apply to this app.

## Preservation approach

The migration retains the original HTML, CSS, fonts, images, and browser scripts. Next.js generates real pages with the original body classes, metadata, and ordered styles/scripts. The React page component preserves trusted exported markup because Elementor widgets depend on its exact classes and data attributes. Navigation uses ordinary links so the original scripts receive a fresh document lifecycle on each page.

This is a compatibility migration, not a rewrite of Elementor widgets into React. The design source remains in `source/prestigewasteremoval-main/`. Edit the page HTML or static assets there, then restart development or rebuild. `scripts/prepare-site.mjs` creates `generated/pages.json` and copies assets into `public/` before development/build. Generated files are ignored by Git.

- `pages/[[...slug]].jsx`: generates exported routes; unknown routes return 404.
- `pages/_document.jsx`: original head, body attributes and browser scripts.
- `components/LegacyPage.jsx`: preserves the original page DOM.
- `next.config.mjs`: trailing slashes and legacy URL redirects.
- `source/prestigewasteremoval-main/static/config.js`: existing form settings.

## Existing form behavior

Contact, employment, and newsletter forms retain the repository's validation and email-draft behavior. They do not send email automatically. Optional existing contactEndpoint and newsletterEndpoint settings accept an HTTPS endpoint supporting multipart FormData. Email drafts cannot attach uploaded files automatically; applicants must attach their resume in their email app.

## Verify

```sh
npm run prepare:site
npm test
npm run build
npm start
# In a second terminal:
npm run test:browser
```

Browser verification uses installed Chrome/Edge on Windows or Playwright Chromium elsewhere (`npx playwright install chromium`). Override CHROME_PATH or TEST_BASE_URL when needed. It checks all routes at desktop/mobile widths, compares source-versus-Next screenshots, and exercises menu, search, form validation/draft generation, and 404 behavior. Screenshots and reports go to artifacts/.

The source XML sitemaps retain their relative URLs. Update sitemap/canonical URLs for your final production domain before submitting sitemaps.

## Migration validation

The production build and preservation tests passed. Browser verification covered all 20 routes at 1440px and 390px with no horizontal overflow, JavaScript/hydration errors, or missing local images. Ten full-page comparisons (home, about, services, contact, and employment at both widths) showed no visual differences. Desktop navigation, mobile menu/Escape dismissal, search/result navigation, required-field validation, email-draft generation, and unknown-route 404 behavior passed.

External Gravatar author avatars could not load in the test environment; their original URLs are retained. The detailed results are in artifacts/browser-report.json after running the browser checks.
